# KuroCat 可动角色包标准（rig 扩展）

> 目标：让外部制作的角色，动作能力对齐原生「大肥鱼」。
> 适用对象：`%APPDATA%\kuro-cat-pet\skins\` 下的自定义角色，以及内置角色。
> 关系：本文是 `CHARACTER-PACK.md`（v2 基础格式）的**叠加层**，不推翻它。v2 写的字段全部有效。

---

## 0. 一句话结论

**角色能动到什么程度，由素体留了多少白决定，不由画得多好决定。**

大肥鱼之所以能甩尾、捂眼、跟手、泛红，不是因为它的图精细，而是因为它的 4 张 PNG 是**素体**：
没有手、没有尾巴、没有瞳孔、没有腮红。所有这些部件都是运行时用参数画上去的。
外部角色沿用同一套留白规则，就能拿到同一套动作能力。

---

## 1. 能力分级

角色包分三级，制作前先声明目标等级。等级只由素材拆分方式和 `rig` 配置决定。

| 等级 | 名称 | 手上有什么 | 能做什么 | 典型代表 |
|---|---|---|---|---|
| **L0** | 整图贴图 | 4 张整图（手和尾烘焙在身体里） | 呼吸、眨眼、点击换表情、整体拖拽 | 旧版四图皮肤 |
| **L1** | 分层 | 身体、瞳孔、手、配件分开 | L0 全部 + 瞳孔跟鼠标 + 手压在键帽上 + 有限位移 | 当前 v2 规范的上限 |
| **L2** | 可动骨架 | 分层 + **素体留白**（无手无尾无瞳） | L1 全部 + 手臂 IK 跟手/跟键帽 + 程序化尾巴 + 打字腮红 + 隐私捂眼 + 探头 | 大肥鱼 |

**本文档定义 L2。** L1 仍然合法，但不再推荐作为新角色目标。

判定 L2 的三个硬条件，缺一不可：

1. 身体帧**没有手臂**、**没有尾巴**、**没有瞳孔**；
2. 每个关节在 `rig` 里声明了归一化坐标；
3. 手臂和尾巴由渲染器绘制，素材只提供"手本身"和"身体"。

## 2. 素体规范（强制）

### 2.1 必须留白的部位

身体帧（`idle` / `blink` / `happy` / `shy` 各帧）**不得包含**下列像素：

| 部位 | 为什么不能烘焙进身体 | 替代方案 |
|---|---|---|
| 双臂、袖子、袖口 | 手臂要跟鼠标和键帽做 IK，静态图无法伸缩 | `rig.arms` 程序化绘制 |
| 手掌、手指 | 手要往复按压、要被拎起时下垂 | `hand-*.png` 单层贴图 + 程序化手臂 |
| 尾巴 | 要甩动、要打键帽、要绕过身体 | `rig.tail` 程序化绘制 |
| 瞳孔 | 要独立跟随视线 | `pupil-*.png` 独立层 |
| 腮红 | 要按打字热度连续变化透明度与尺寸 | `rig.blush` 程序化绘制 |
| 刘海/呆毛（如要做飘动） | 要单独摆动，且不能被脸挡住 | 独立 `accessory` 层 |

### 2.2 允许留在身体里的

- 耳朵、脸、躯干、腿、脚、衣服主体
- 眼睛的**眼白、眼眶、睫毛、眉毛、眼皮线**（静态部分）
- 固定的装饰（项圈、纽扣、围裙）：它们不跟随任何输入

### 2.3 肩点必须落在实心身体内

程序化手臂从肩点长出来，第一笔是一个半径 `sleeve.shoulderRadius` 的圆。
因此：

> 肩点必须位于身体轮廓内部，且距最近的透明边界 **≥ 1.5 倍 shoulderRadius**（默认约 14px 绘制像素）。

否则圆的边缘会悬空，出现"断臂"。这是 L2 素材最常见的返工原因。

### 2.4 导出纪律

| 规则 | 说明 |
|---|---|
| **禁止裁透明边** | 所有图层必须与 `canvas.width × canvas.height` 完全同尺寸。裁掉透明边会让所有归一化锚点整体错位。 |
| 帧间零位移 | 同一动画的各帧，身体不得平移；只用局部形变（呼吸压扁、眼睛闭合）。 |
| 上半身不动的位置不动 | 呼吸帧只能改躯干高度，头和肩的 y 偏差建议 ≤ 2px，否则手臂根部会跳。 |
| 图层可留空 | 某帧该层不显示时，用 `actions` 过滤，不要导出一张空图。 |

## 3. 图层与 z 序

z 序从后到前，共 9 档。`rig` 生成的部件插入其中固定的位置，**不可调整**。

| z | 内容 | 来源 | 说明 |
|---|---|---|---|
| 1 | 背景装饰 | `role: "back"` 图层 | 可选 |
| 2 | 身体帧 | `animations.*` | 素体 |
| 3 | 尾巴（后段） | `rig.tail` | 尾巴要从身体后面绕出 |
| 4 | 眼球、瞳孔、眉眼细节 | `role: "pupil-*"` / `"eye-details"` | 静态细节 + 可动瞳孔 |
| 5 | 腮红 | `rig.blush` | 必须在眼睛下方、鼠标之下 |
| 6 | 迷你鼠标、机械键盘 | 引擎内置 | 固定层，任何素材都不能盖过它的底 |
| 7 | 手臂、袖口、手 | `rig.arms` + `hand-*.png` | 压住键帽 |
| 8 | 尾巴（前段、甩击） | `rig.tail` | 甩尾时覆盖键帽 |
| 9 | 前景配件 | `role: "accessory"` / `"front"` | 可选 |

两条硬约束：

- **手必须在键帽之上**，这是 v2 已经解决的问题，L2 继承。
- **腮红必须在手之下**，否则捂眼时腮红会浮在手背上。

## 4. 坐标规范

### 4.1 归一化定义

所有锚点写作 `[x, y]`，取值 `0..1`，含义是：

```
x = 像素x / canvas.width
y = 像素y / canvas.height
```

**相对于整张画布，不是相对于角色包围盒。** 这条与"禁止裁透明边"配套使用。

### 4.2 画布四参数

```json
"canvas": {
  "width": 224,
  "height": 278,
  "drawWidth": 262,
  "baseY": 364,
  "pivotOffset": 48
}
```

| 字段 | 作用 | 建议 |
|---|---|---|
| `width` / `height` | 素材设计画布 | 沿用 224×278 可直接复用大肥鱼全部实测锚点 |
| `drawWidth` | 桌面上实际绘制宽度（px） | 262 是原生值；108 屏自动放大到 268 |
| `baseY` | 角色底部与键盘的相对位置 | 364；想让角色坐得更低就加大 |
| `pivotOffset` | 旋转支点距底部的偏移 | 48；改它会同时移动手臂和尾巴的基准 |

`baseY` / `pivotOffset` 不需要改。它们和大肥鱼渲染器共用同一套定位常量。

### 4.3 锚点标注方法（出图流程）

不要凭眼睛估。在出图阶段用辅助层标十字：

1. 在 Aseprite / Photoshop 里新建一层，在候选关节位置画 5px 十字；
2. 记录十字中心的像素坐标，除以画布尺寸得到归一化值；
3. 导出时**不包含**该辅助层；
4. 填完 `rig` 后把十字渲染出来复核一遍（见第 8 节验收项 2）。

### 4.4 大肥鱼实测锚点（可直接借用）

同一画布比例下，这些值经过了实机验证：

| 锚点 | 归一化坐标 | 用途 |
|---|---|---|
| 左肩 | `[0.390, 0.653]` | 左臂起点 |
| 右肩 | `[0.610, 0.653]` | 右臂起点 |
| 尾根 | `[0.560, 0.785]` | 尾巴起点 |
| 左眼泪点 | `[0.390, 0.476]` | 捂眼目标 / 视线原点 |
| 右眼泪点 | `[0.598, 0.476]` | 捂眼目标 / 视线原点 |
| 左腮红 | `[0.372, 0.562]` | 腮红中心 |
| 右腮红 | `[0.616, 0.562]` | 腮红中心 |

注意左右不对称（0.598 vs 0.610、0.372 vs 0.390），这是原画本身有轻微手绘偏移。**照抄即可，不要强行对称**，强行对称反而会露出对不齐。

## 5. rig 配置

### 5.1 版本兼容

`rig` 是 `schemaVersion: 2` 的**可选顶层字段**。不升版本号，原因：

- 当前解析器遇到未知字段是忽略，不会报错；
- 旧渲染器读到带 `rig` 的包，会照常按 L1 渲染，不会崩；
- 新渲染器读到没有 `rig` 的包，会照常按 L1 渲染。

所以加 `rig` 是**纯增量**，不存在破坏性升级。

```json
{
  "schemaVersion": 2,
  "id": "my-character",
  "name": "我的角色",
  "canvas": { ... },
  "animations": { ... },
  "layers": [ ... ],
  "rig": { "version": 1, "arms": [ ... ], "tail": { ... }, "blush": { ... }, "privacy": { ... } },
  "motion": { ... },
  "audio": { ... }
}
```

### 5.2 `rig.arms`

每个手臂一个条目。`handLayer` 引用 `layers[].id`，那块手部贴图只画手本身，不含前臂。

```json
{
  "id": "left-arm",
  "side": "left",
  "handLayer": "left-hand",
  "shoulder": [0.390, 0.653],
  "style": "sleeve",
  "sleeve": {
    "shoulderRadius": 9.2,
    "cuffRadius": 12.0,
    "gradient": ["#1f223b", "#272b4b", "#31365e"],
    "outlineColor": "#181a2e",
    "outlineWidth": 2.4,
    "curveBias": 2.5
  },
  "cuff": {
    "lineColor": "rgba(205,212,232,0.85)",
    "lineWidth": 1.6,
    "buttonColor": "#e7c67b",
    "buttonRadius": 1.5,
    "inset": 5.5
  },
  "ruffle": {
    "count": 5,
    "radius": 4.7,
    "spacing": 4.4,
    "color": "#f8f9fe",
    "outlineColor": "#252844",
    "outlineWidth": 1.8
  },
  "hand": {
    "rx": 8.4,
    "ry": 8.2,
    "color": "#fde7df",
    "outlineColor": "#3d2c35",
    "outlineWidth": 2.0,
    "highlight": "rgba(255,255,255,0.72)",
    "highlightRadius": 2.3,
    "highlightOffset": [-2.2, -2.2],
    "squashGain": 0.14,
    "squashLoss": 0.10
  },
  "reach": { "rest": 72, "pointer": 88, "pressSquash": 1.0 },
  "follow": { "smoothing": 26, "idleOffset": [-15, 34], "cheerOffset": [-14, 4] }
}
```

字段说明：

| 字段 | 含义 | 取值依据 |
|---|---|---|
| `style` | 手臂形态 | `sleeve` 袖子（收口渐宽）、`tube` 直筒（裤腿/机械臂）、`fur` 毛腿（无袖角色） |
| `sleeve.shoulderRadius` | 肩根半径 | 决定素体肩部留白深度（见 2.3） |
| `sleeve.cuffRadius` | 袖口半径 | 比肩根大 20–35% 才有"喇叭袖"感 |
| `sleeve.gradient` | 3 段线性渐变，从肩到腕 | 纯色角色填同一个色值 3 次 |
| `sleeve.curveBias` | 手臂中段的侧向弯曲量（px） | 2.5；填 0 是笔直硬棍 |
| `cuff.buttonRadius` | 0 表示不要金扣 | 非制服装角色设 0 |
| `ruffle.count` | 0 表示不要荷叶边 | `fur` 风格一律设 0 |
| `hand.rx/ry` | 手椭圆半径 | 近圆手才可爱；`rx:ry` 控制在 1.05 以内 |
| `hand.squashGain/Loss` | 按压时长轴放大/短轴压缩 | 0.14 / 0.10 是原生值 |
| `reach.rest` | 待机与键盘模式下的最大臂长 | 72 |
| `reach.pointer` | 鼠标模式下的最大臂长 | 左 88 / 右 86 / 108 屏 96 |
| `follow.idleOffset` | 待机时手相对肩点的偏移 | `[-15, +34]`，即垂在身体两侧 |
| `follow.cheerOffset` | 开心时手相对肩点的偏移 | `[-14, +4]`，即举到肩侧 |

`handLayer` 的手部贴图建议就是"手 + 极短的一截腕"，长度不超过 `cuffRadius`。
手臂中段由渲染器补，贴图给太长会在弯折时露出直线段。

### 5.3 `rig.tail`

```json
{
  "root": [0.560, 0.785],
  "style": "whale",
  "length": 150,
  "width": 26,
  "gradient": ["#2f3d63", "#3f4f78"],
  "outlineColor": "#1b2340",
  "outlineWidth": 2.0,
  "rest": { "tip": [0.78, 0.80], "ctrlOffset": [52, -6] },
  "idle": { "wagDeg": 3.5, "periodMs": 3200 },
  "slap": { "enabled": true, "durationMs": 380, "trigger": "keyboard", "crossBias": 0.55 }
}
```

| 字段 | 含义 | 建议 |
|---|---|---|
| `style` | 尾巴形态 | `whale` 鲸尾（分叉）、`cat` 猫尾（渐细）、`plume` 毛尾（蓬松） |
| `rest.ctrlOffset` | 待机时贝塞尔控制点相对尾根的偏移 | `[52, -6]`，决定自然垂度 |
| `idle.wagDeg` | 待机摆动角度 | 2–5 度；超过 6 会显得焦躁 |
| `slap.trigger` | 甩击触发源 | `keyboard` 按远端键触发、`mouse` 鼠标点击触发、`never` 关闭 |
| `slap.crossBias` | 甩到对侧时的绕身权重 | 0.55；这套值保证尾巴不穿过躯干 |

**尾巴必须先画一次后段（z=3）再画一次前段（z=8）。** 只画一层，甩击时会穿透身体。

### 5.4 `rig.blush`

```json
{
  "anchors": { "left": [0.372, 0.562], "right": [0.616, 0.562] },
  "radius": { "min": [11.5, 6.2], "max": [16.0, 8.4] },
  "color": ["rgba(255,110,148,0.46)", "rgba(255,138,170,0.22)"],
  "mergeAt": 0.08,
  "hatchAt": 0.52,
  "hatch": { "offsets": [-3.4, 0, 3.4], "color": "rgba(235,88,132,0.36)", "width": 1.05 },
  "driver": { "riseRate": 2.2, "fallRate": 0.65 }
}
```

| 字段 | 含义 | 说明 |
|---|---|---|
| `radius.min → max` | 腮红从 0 到 1 时的椭圆半径 | 线性插值 |
| `color` | 径向渐变两停颜色 | 第 3 停固定为全透明 |
| `mergeAt` | 低于此热度完全不画 | 0.08 |
| `hatchAt` | 高于此热度追加 3 条斜线 | 0.52 |
| `driver.riseRate` | 打字时升温速率 | 2.2；越大越快脸红 |
| `driver.fallRate` | 停手时降温速率 | 0.65；必须显著小于 riseRate |

腮红靠**打字热度**驱动，不是随机。热度来源：按键事件密度累积，停手后指数衰减。

### 5.5 `rig.privacy`

输密码时双手捂住眼睛。这是 L2 相对 L1 最有辨识度的能力。

```json
{
  "mode": "cover-eyes",
  "eyeAnchors": { "left": [0.390, 0.476], "right": [0.598, 0.476] },
  "bob": { "amplitude": 1.4, "periodMs": 785 },
  "expression": "blink"
}
```

| 字段 | 含义 |
|---|---|
| `mode` | `cover-eyes` 双手捂眼；`turn-away` 整体转向（素材需配 turnaround 帧）；`none` 不做处理 |
| `eyeAnchors` | 手要停的位置，必须是瞳孔中心 |
| `bob.amplitude` | 捂眼时左右手反向轻微上下浮动，制造"害羞发抖"感 |
| `expression` | 进入隐私模式时强制播放的表情名 |

`mode: "cover-eyes"` 要求 `rig.arms` 完整，否则会变成两只手飘在脸前。

## 6. 行为解算规范

### 6.1 手部目标：五级优先级

每帧按顺序匹配，命中即停。**优先级顺序不可调**，否则捂眼会被鼠标抢走。

| 级 | 条件 | 双手目标 | 表情 | 身体 |
|---|---|---|---|---|
| 1 | `privacyMode` | 双眼锚点 + 反向浮动 | `blink` | 不动 |
| 2 | `petEnergy > 0.25` 且非隐私 | 肩点 + `cheerOffset` + 正弦摆动 | `happy` | 轻微上浮 |
| 3 | 鼠标键按下，或鼠标活动 < 900ms | 鼠标键位 + `pressOffsetY` | `idle` | 侧倾 `mouseLean` |
| 4 | 键盘按键 < 380ms，或该键仍按住 | 对应键帽中心 | `idle` | 不动 |
| 5 | 其余 | 肩点 + `idleOffset` | `idle` | 呼吸 |

### 6.2 手臂长度钳制

肩点到手腕的直线距离受 `reach` 限制，超出则沿方向等比缩短（手停在可达边界上，不瞬移）。

| 场景 | 上限 |
|---|---|
| 键盘模式 | `reach.rest`（72） |
| 鼠标模式，左臂 | `reach.pointer`（88） |
| 鼠标模式，右臂 | 86 |
| 108 分辨率屏 | 96 |

### 6.3 跟随平滑

手的位置用指数插值趋近目标：

```
pos += (target - pos) * (1 - exp(-smoothing * dt))
smoothing = 26
```

`26` 是原生值。低于 12 会明显拖沓、像在拉橡皮；高于 40 会抖。

### 6.4 按压形变

鼠标按下时手被压扁：

```
rx = hand.rx * (1 + squash * squashGain)
ry = hand.ry * (1 - squash * squashLoss)
squash 在松开后按 exp(-14 * dt) 衰减
```

### 6.5 视线

瞳孔在锚点附近平移，位移上限由 `layers[].gaze.maxX/maxY`（屏幕像素）给出。
隐私模式下视线锁定不动——此时眼睛应该已经闭上了。

```
skins/<角色名>/
  character.json

  idle-1.png         素体，呼吸形变

  pupil-left.png     仅左瞳孔
  pupil-right.png    仅右瞳孔

  right-hand.png     仅右手

```

### 逐项自检

1. 把 `idle-0.png` 单独打开，**手臂位置必须是透明**；若能看到手的轮廓，回退重做。
2. 把 `idle-0.png` 单独打开，**尾根往下必须是透明**。
3. 瞳孔层只含瞳孔，放大看不能有眼白、睫毛、眼影。
4. 手层只含手，不能带前臂长条。
5. 所有层尺寸与 `canvas` 完全一致。

## 8. 验收标准

七项，全部可测。前 4 项在出图阶段就能验，后 3 项需要跑起来。

| # | 项目 | 判定方法 | 通过标准 |
|---|---|---|---|
| 1 | 素体干净 | 单独打开身体帧 | 手、尾、瞳、腮红位置全透明 |
| 2 | 锚点准确 | 临时渲染锚点十字 | 十字中心落在关节上，偏差 ≤ 2px |
| 3 | 肩部无缝 | 光标移到四角 | 肩点到手腕无断口、无悬空圆边 |
| 4 | 图层对齐 | 叠加所有层 | 无重影、无错位、无裁边导致的偏移 |
| 5 | z 序正确 | 按住鼠标左键 | 手压在键帽上；腮红在手下方 |
| 6 | 捂眼完整 | 触发隐私模式 | 双手完全覆盖双眼，不漏眼白 |
| 7 | 腮红响应 | 连续打字 3 秒 | 出现腮红；停手 4 秒内消退到不可见 |

第 3 项是最容易失败的一项。失败原因九成是肩点没落在实心身体内（见 2.3）。

## 9. 实现映射（当前差距）

标准先立，代码要跟上。当前状态：

| 能力 | 现状 | 需要补的位置 |
|---|---|---|
| 分层、z 序、`actions` 过滤 | 已实现 | `layeredRenderer2d.ts` |
| 瞳孔跟随 | 已实现 | `layeredRenderer2d.ts` `drawLayer` 的 `gaze` 分支 |
| 手部有限位移 + 单色连接臂 | 已实现 | `drawArmConnector`，但只有圆头线条，无渐变/袖口/荷叶边/形变 |
| 手臂跟键帽 | **缺失** | 只响应鼠标，需接入键盘事件与 `reach.rest` |
| 程序化尾巴 | **缺失** | 需新增尾巴绘制（可参考 `dafeiyuRenderer.ts` 的 `drawWhaleTail`） |
| 打字腮红 | **缺失** | 需新增热度累积与径向渐变绘制 |
| 隐私捂眼 | **缺失** | 当前只切 `shy` 帧，需按 `rig.privacy` 改手部目标 |
| `rig` 解析 | **缺失** | `characterPack.ts` 需新增可选类型与解析，缺省值为 L1 行为 |

已实现的部分以 `dafeiyuRenderer.ts` 为参照实现，它的 `drawChubbyArm` 就是 `rig.arms` 的参考实现，
`drawWhaleTail` 就是 `rig.tail` 的参考实现，腮红与捂眼逻辑同样在那份文件里。

## 10. 兼容与迁移

| 情况 | 行为 |
|---|---|
| 无 `rig` 的 v2 包 | 按 L1 渲染，与现在完全一致 |
| 旧四图皮肤（`idle.png` 等） | 继续按 L0 渲染 |
| 有 `rig` 但缺 `handLayer` | 该手臂跳过程序化绘制，退回 L1 位移 |
| `rig.arms` 为空数组 | 视为 L1，不报错 |
| `rig` 字段写错类型 | 逐字段回退默认值，不整体拒绝，避免一个笔误让角色消失 |

原则：**`rig` 的任何错误都不能让角色加载失败**，最差退回 L1。

## 11. 示例：把「比熊1」升级到 L2

现有 `素材/比熊1/` 是 L1：白狗坐姿，手烘焙在身体里，`followMouse: false`。
升级只需四步，不用重画整张图。

### 第 1 步：从身体帧里挖掉手

现有身体帧有两只前爪。做法：

1. 复制 `idle-0.png`，把两只爪子的区域用身体色 + 毛发纹理补平（比熊是白毛，难度低）；
2. 得到的新图作为 `body`，爪子单独保留为 `left-hand.png` / `right-hand.png`；
3. 肩点定在**爪子上方、身体轮廓内**的位置，白狗没有袖子，用 `style: "fur"`。

⚠️ 不要用"把爪子涂成透明"的方式：透明洞会露出键盘，必须用身体色补平。

### 第 2 步：填 `rig.arms`

比熊没有袖子，参数大幅简化：

### 第 3 步：加腮红

比熊已有腮红画在身体里，L2 要求抠掉改程序化。若要保留静态腮红，
就**不要**配置 `rig.blush`——两者同时存在会叠出一块过红的斑。

### 第 4 步：验证

按第 8 节七项走一遍。重点看第 3 项（肩部无缝），比熊是白毛 + 浅描边，
缝隙比深色角色更容易看出来。

### 不升级也可以

L1 的比熊在桌面上是能用的：爪子搁在键盘上，表情齐全。
升级 L2 的收益是"手会跟着鼠标动、会捂眼、会脸红"，代价是素材要重做一版。
按目标定，不要盲目追等级。

## 12. 附：为什么原生角色能做到

不是为了对比，是为了让标准有出处。大肥鱼的实现路径：

```
素材：4 张 notail_*.png（224×278，无手无尾）
  ↓
dafeiyuRenderer.ts
  ├─ renderBody()        画素体 + 程序化眼神高光
  ├─ renderForeground()  画手、尾巴、水花
  ├─ drawChubbyArm()     袖子贝塞尔 + 渐变 + 袖口 + 荷叶边 + 圆手
  ├─ drawWhaleTail()     双段贝塞尔，甩击时绕身
  └─ 腮红               径向渐变 + 3 条斜线，由打字热度驱动
```

关键点：**素材只提供"不变的形状"，变化的全部交给参数。**
这就是本文档要求素体留白的原因。
